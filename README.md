# KART RUSH — FOREST RACING PARK

HTML / CSS / Vanilla JavaScript / Three.js로 만든 6인 3D 아케이드 카트 레이싱 게임입니다. 공개 사이트에서는 온라인 명예의 전당을 함께 사용합니다.

온라인 플레이: [apex-evergreen-kart.netlify.app](https://apex-evergreen-kart.netlify.app/) · [GitHub 소스](https://github.com/reiner5427-eng/kart-racing)

Netlify는 `netlify.toml`의 `node scripts/build.cjs`로 정적 파일 3개를 `dist/`에 준비하고 `netlify/functions/`의 기록실·1:1 방 서버 함수를 배포합니다. 현재 공개 사이트는 연결된 Netlify 프로젝트에 업로드 배포했으며, GitHub 푸시만으로 자동 배포되지는 않습니다.

## 실행

1. `index.html`을 Chrome 또는 Edge로 엽니다.
2. Three.js CDN 및 웹 폰트를 읽기 위해 인터넷 연결이 필요합니다. 폰트 연결이 안 되면 시스템 폰트로 대체합니다. Three.js는 jsDelivr 실패 시 unpkg로 재시도합니다.
3. 로컬 서버를 선호하면 Node.js가 있는 환경에서 `node server.cjs` 실행 후 `http://127.0.0.1:4173`에 접속합니다. 패키지 설치는 필요 없습니다.

`index.html` 직접 실행이나 `server.cjs` 사용 시 온라인 API가 없으므로 이 기기의 `localStorage` 기록을 표시합니다. 모든 기기가 공유하는 명예의 전당은 위 Netlify 공개 사이트에서 이용할 수 있습니다. 데스크톱은 키보드, 모바일은 화면의 터치 조작 패드로 플레이할 수 있습니다.

## 플레이 흐름

메인 → 이름 입력(한글/영문/숫자, 최대 12자) → 캐릭터 선택 → 모드 선택 → 3·2·1·GO → 3랩 레이스 → 결과 → **나의 기록 등록** → 약 3.6초 3D 기록 카드 → 명예의 전당.

결과 화면에서 랩별 기록을 읽은 뒤 **나의 기록 등록**을 누르면 기록 연출이 시작됩니다. 명예의 전당에서 다시 하기, 캐릭터 선택, 메인 메뉴로 이동할 수 있습니다.

## 온라인 1:1 레이스

두 기기에서 공개 사이트를 열고 **1:1 로비**로 들어갑니다. 방장은 이름·캐릭터를 고른 뒤 **방 만들기**를 누르고 화면의 6자리 입장코드를 상대에게 전달합니다. 상대는 이름·캐릭터를 고른 뒤 **다른 게임 입장하기**에 코드를 입력합니다. 입장이 완료되면 두 화면에 카운트다운이 나타나고 3랩 스피드전이 시작됩니다. 데스크톱 키보드와 모바일 터치 조작을 모두 사용할 수 있습니다.

서버가 방 생성·참가자 인증·동시 출발 시각·차량 상태·완주 결과를 공유합니다. 카트 위치는 약 0.32초 간격으로 전송하고 상대 화면에서 부드럽게 보정합니다. 네트워크 상태에 따라 상대 위치가 조금 늦게 보일 수 있습니다. 두 사람이 완주하면 3랩 총시간이 짧은 쪽이 승리합니다. 상대가 **경기 나가기**를 누르면 남은 쪽이 승리하고, 한 명이 완주한 뒤 상대 연결이 20초 이상 끊기면 완주한 쪽이 승리합니다. 결과 화면에는 두 사람의 기록과 승패가 표시됩니다. 1:1 기록은 **로컬 백업과 온라인 명예의 전당 어느 쪽에도 등록하지 않습니다.**

1:1 경기 중에는 타이머 공정성을 위해 일시정지가 비활성화됩니다. 두 기기 모두 인터넷 연결이 필요하고 방은 생성 후 2시간 동안 유효합니다. 방 코드는 해당 경기에 참가할 상대에게만 전달하세요. 브라우저를 강제로 닫으면 상대 화면에는 연결 끊김이 표시되며, **경기 나가기**를 누르면 명확한 기권 처리로 전환됩니다. 실시간 위치와 완주 정보는 클라이언트에서 보내는 방식이므로 경쟁 대회 수준의 부정행위 방지 기능은 아닙니다.

## 캐릭터

추가로 제공된 이미지 및 사용자의 잠만보 추가 요청에 따라 다음 6종을 Three.js primitive geometry로 직접 모델링했습니다. 외부 모델·텍스처·음원 파일을 사용하지 않습니다. 참고 이미지의 정교한 원화와 동일한 모델이 아닌 단순화한 3D 표현입니다.

| 캐릭터 | 형태 / 테마 |
|---|---|
| 피카츄 | 노란 몸, 긴 검은 귀 끝, 붉은 볼, 번개 꼬리 |
| 이브이 | 갈색 몸, 긴 귀, 크림색 목털과 꼬리 끝 |
| 파이리 | 주황색 몸, 밝은 배, 불꽃 꼬리 |
| 이상해씨 | 청록색 몸, 얼굴 무늬, 등에 초록 씨앗 |
| 피죤 | 붉은 볏, 부리, 펼친 깃털 날개 |
| 잠만보 | 청록색 몸, 넓은 크림색 배, 감은 눈 |

모든 캐릭터는 같은 플레이어 성능을 갖습니다. 선택하지 않은 5명이 AI에 중복 없이 배정됩니다. 선택 카드와 명예의 전당 썸네일도 실제 3D 모델을 렌더링한 이미지입니다.

## 조작법

| 키 | 동작 |
|---|---|
| W / ↑ | 가속 |
| S / ↓ | 브레이크, 정지 후 후진 |
| A·D / ←·→ | 조향 |
| Shift + 조향 | 드리프트 |
| Space | 스피드전 부스터 사용 |
| E / Ctrl | 아이템전 아이템 사용 |
| R | 마지막 정상 체크포인트 복귀 |
| Esc | 일시정지 / 계속 |
| F2 | 물리·랩·FPS 디버그 |
| M | 음소거 전환 |

캐릭터 선택에서는 ←·→ / Enter도 사용 가능합니다. 창이 포커스를 잃거나 숨겨지면 자동 일시정지합니다.

### 모바일 터치 조작

레이스가 시작되면 왼쪽의 ◀·▶로 조향하고 오른쪽 **GO**를 누르고 있는 동안 가속합니다. **BRAKE**는 브레이크/후진입니다. **DRIFT**를 누른 채 ◀ 또는 ▶를 함께 누르면 드리프트하고, 손을 떼면 충전 단계에 따른 미니 터보가 발동합니다. 모드에 따라 **BOOST** 또는 **ITEM** 버튼이 표시됩니다. 화면 위쪽 **Ⅱ**는 일시정지, **↶**는 체크포인트 복귀입니다. 가속·조향·드리프트 버튼은 여러 손가락으로 동시에 누를 수 있습니다. 버튼에서 손을 떼거나 앱을 벗어나면 입력이 해제됩니다. 세로와 가로 화면에 맞춰 조작 배치가 달라집니다.

## 주행 / 스피드전

월드 좌표의 속도 벡터를 전진·횡속도로 분해하여 가속, 브레이크, 항력, 횡그립을 적용합니다. 고속에서 조향 민감도가 줄고, 잔디에서 감속되며, 울타리에서는 충돌 속도 성분이 반사됩니다.

Shift와 조향을 유지하면 횡그립이 낮아지며 차체 방향과 이동 방향이 달라집니다. 드리프트 충전 0.6 / 1.35 / 2.3초에 1·2·3단계가 됩니다. 해제 시 단계에 맞는 미니 터보가 자동 발동합니다. 스피드전에서는 드리프트 약 3.23초마다 부스터를 충전하고 최대 2개 보관합니다. Space 부스터는 기본 1.8초입니다.

카메라는 속도와 부스터에 따라 거리·FOV를 바꾸고 감쇠 추적합니다. 드리프트 자국·연기/스파크, 부스터 파티클 및 스피드 라인이 표시됩니다.

## 아이템전

트랙의 부유 큐브에서 최대 2개를 획득합니다. 획득한 큐브는 4초 후 재생성됩니다. AI도 같은 박스·아이템 규칙을 사용합니다.

| 아이템 | 기능 |
|---|---|
| 유도 로켓 | 전방에서 가장 가까운 상대 추적, 감속과 짧은 조작 불가 |
| 물폭탄 | 전방으로 포물선 투척, 1.1초 후 반경 7m 폭발, 감속과 조향 감소 |
| 미끄럼 트랩 | 뒤에 설치, 접촉한 상대의 감속과 스핀 |
| 실드 | 3초 보호 또는 공격 1회 방어 후 소멸 |
| 순간 부스터 | 2초 가속 / 최고속도 증가 |

선두권은 실드·부스터, 후미권은 로켓·물폭탄에 가중치를 줍니다. 물폭탄은 사용자도 폭발 반경 내에 있으면 영향을 받습니다.

## 트랙 / AI

폐곡선 레이싱 라인을 기반으로 직선, 숲길, S 코너, 나무 다리, 헤어핀, 터널을 연결합니다. 5대의 AI는 전방 목표 지점을 향해 실제 차량 물리로 조향합니다. 속도, 가속, 레이싱 라인, 코너 감속 및 드리프트가 서로 다릅니다. 저속 고착 시 마지막 체크포인트로 복귀합니다.

플레이어가 완주한 뒤에도 남은 AI는 주행을 계속합니다. 아직 완주하지 않은 AI는 결과 화면에 `주행 중`으로 표시되며 도착하면 시간이 갱신됩니다. 결과 순위는 완주자 도착 순서, 미완주자 체크포인트 진행도 순입니다.

## 랩과 시간

24개 구간 체크포인트를 정방향 순서로 통과하고 피니시를 통과해야 한 랩으로 인정합니다. 역주행, 중간 구간 건너뛰기, R 복귀는 랩 수나 시간을 초기화하지 않습니다. 랩 타이머는 GO부터 시작하며 첫 랩은 스타트 그리드에서 라인까지의 시간도 포함합니다.

`performance.now()` 기반 requestAnimationFrame 타임스탬프의 경과 밀리초를 저장합니다. 일시정지와 카운트다운은 기록에 포함하지 않습니다. 큰 프레임 지연 시 물리는 최대 50ms까지만 보정하지만 실제 경과 시간은 기록에 포함하여 느린 프레임으로 기록이 유리해지지 않습니다. 표시 형식은 공통 `formatTime()`의 `00:42.318`입니다.

## 명예의 전당 / 저장

일반 6인 레이스의 3랩 정상 완주자만 등록합니다. **1:1 경기는 등록하지 않습니다.** 레이스 순위와 별개로 **BEST LAP 오름차순** TOP 10을 유지합니다. Netlify 사이트에서는 `/api/leaderboard` 함수가 기록을 검증하여 Netlify Blobs의 사이트 전체 저장소에 보관합니다. 다른 기기에서 같은 사이트를 열면 동일한 순위를 볼 수 있습니다. 등록된 플레이어 이름과 기록은 모든 방문자에게 공개됩니다.

브라우저 백업용 localStorage 키: `kartRushHallOfFame`

각 항목: `id`, `playerName`, `characterId`, `characterName`, `bestLapTime`, `totalTime`, `mode`, `date`, `lapTimes` (시간은 숫자 밀리초).

저장된 JSON 파싱·쓰기 오류를 처리하고, 잘못된 형식의 항목은 무시합니다. 같은 레이스의 중복 등록을 막습니다. 기본적으로 같은 이름의 여러 기록을 허용합니다. 새 기록에 강조 효과, 1위 기록에 축하 파티클을 표시합니다. 온라인 저장이 실패하면 이 기기의 백업을 표시하고 등록 재시도 버튼을 제공합니다. `이 기기 기록 삭제`는 확인 후 로컬 백업만 지우며 온라인 순위는 지우지 않습니다. 이전 버전에서 만든 로컬 기록은 온라인에 자동 게시되지 않습니다.

서버는 이름·캐릭터·모드·3랩 시간과 합계를 검증합니다. 계정 및 서버 권위형 레이스 검증이 없으므로 고의로 조작한 요청까지 완전히 차단하는 경쟁용 순위 시스템은 아닙니다.

## CONFIG 조절

`game.js` 상단의 `CONFIG`에서 주행 성능, 드리프트 단계, 부스터 시간, 아이템 확률, 트랙 폭 및 파티클 상한을 조절할 수 있습니다.

- `vehicle`: acceleration, maxSpeed(m/s), braking, steering, lateralGrip, drag
- `drift`: grip, chargeRate, level1/2/3
- `boost`: duration(초), speedMultiplier
- `item`: respawnTime(밀리초), shieldDuration(밀리초), missileSpeed
- `item.weightsFront / weightsBack`: 로켓·물폭탄·트랩·실드·부스터 순서의 상대 가중치
- `leaderboard.maxEntries`: 기본 10
- `leaderboard.keepBestOnly`: true이면 이 기기의 백업에서 동일 이름·모드의 최고 기록만 유지. 온라인 기록은 동일 이름을 허용하고 BEST LAP TOP 10으로 정렬

경기는 6명·3랩으로 구성되어 있으며 HUD와 기록 등록 조건도 이에 맞춰져 있습니다. 인원·랩 수를 바꾸려면 해당 UI와 검증 조건도 함께 수정해야 합니다.

## 파일 / 검증

- `index.html`: 진입점, CDN 재시도
- `style.css`: 메뉴·레이스 HUD·기록실
- `game.js`: 모델, 서킷, 물리, AI, 아이템, 상태 및 기록 시스템
- `server.cjs`: 선택 사항인 로컬 정적 서버
- `netlify/functions/leaderboard.mts`: 온라인 기록 읽기·등록 API
- `netlify/functions/duel.mts`: 1:1 방 생성·입장·실시간 위치·완주 판정 API
- `netlify/functions/duel-cleanup.mts`: 만료된 방 데이터를 매일 정리
- `netlify/functions/_shared/records.mts`: 기록 검증 및 정렬
- `package.json`, `pnpm-lock.yaml`: 서버 함수 의존성. 로컬 정적 실행에는 설치 불필요
- `smoke-test.cjs`, `integration-test.cjs`: 개발 환경의 Playwright 테스트. 게임 실행에는 필요 없음. 테스트 파일의 Playwright 경로는 이 작업 환경 기준입니다.
- `mobile-test.cjs`: 휴대폰 크기의 브라우저에서 실제 다중 터치 입력·드리프트·일시정지를 확인합니다.
- `duel-test.mjs`, `duel-browser-test.cjs`: 서버 방 로직 및 두 기기 1:1 브라우저 흐름을 확인합니다. 브라우저 테스트는 `THREE_TEST_SCRIPT`에 Three.js 스크립트의 로컬 경로를 지정하면 CDN에 접속할 수 없는 개발 환경에서도 실행됩니다.

통합 테스트는 브라우저에 전달하는 코드 사본에만 자동 운전 및 시간 진행 장치를 붙입니다. 배포 게임에는 자동 완주나 기록 생성용 치트가 없습니다. 실제 차량 물리와 체크포인트를 통과시켜 양 모드 완주, 기록 카드, 저장·정렬·중복 방지 등을 검사합니다.
